# 产品愿景

> **🔎 实现状态（对齐真实代码 · 2026-08-13）** — 本文是长期产品愿景（TARGET），能力地图列的是目标能力，不代表全部已落地。当前代码**已实现+接线**的闭环包含：简历**文本**摄取/诊断、押题、自适应模拟面试、报告/复盘/成长档案/职业路径/学习计划（确定性派生，单一源=assessment_report）、B 端招聘（岗位/申请/人才库 + 多方 RLS）、支付权益 no-oversell saga、语音（TTS/ASR，限频）和约 25 个 SSR 页面。**图片简历 OCR 当前在所有环境 fail-closed**：`OCR_ENABLED=1` 会拒绝 API 组合根，缺失或非 `1` 的开关在入口前返回 `422 image_ocr_unavailable`，不会创建 OCR 额度、工件或调用账本；它不能被称为已接线能力或百炼验证。**🟠 未接线/桩**：扫描型 PDF（无文本层）OCR（需逐页渲染成图，快随项）；联网找真题 web-explore **机制已接且默认开启**（`DEFAULT_WEB_ALLOWLIST` 6 个官方文档源作 CRAG fallback 外呼；env 设空串才关），但**真实策展题库源表 + 审核门 + 扩召回未建**、本地种子库仍仅约 32 条；跨会话**已接**精确 hash 题目去重 + 历史弱项软偏置能力选择（不动分数/难度/成长曲线），**未接**语义记忆/信念画像（`rememberFact`/`recallMemories` 目前是死代码）。**⬜ 规划**：3D 数字人、微信扫码登录、答题辅助教练层、运营后台完整化等。

## 一句话定位

Meetwise（知面）是一个以面试训练为中心的 AI 求职准备平台，帮助用户理解岗位、诊断能力、优化简历、预测问题、模拟面试、复盘表现，并形成可持续的职业成长路径。

## 产品中心

产品中心是“面试准备”，但不止于面试。

核心路径：

```text
用户画像 -> 简历与经历 -> 岗位/JD -> 能力差距 -> 面试训练 -> 报告复盘 -> 学习计划 -> 下一轮迭代
```

## 目标用户

| 用户 | 需求 |
| --- | --- |
| 求职者 | 简历诊断、岗位匹配、押题、模拟面试、报告复盘 |
| 转岗者 | 职业路径分析、技能差距、学习计划、项目包装 |
| 应届生 | 行测/HR/通用面试训练、表达训练、简历基础优化 |
| 经验开发者 | 针对目标岗位的深度技术面、项目深挖、架构表达 |
| 运营者/内容维护者 | 题库、岗位画像、模型效果和运营数据管理 |

## 产品形态：求职者优先 + 隔离的企业招聘第二产品线

主体是 C 端求职者备战。企业招聘线（公司维护内部人才库 + 用同一引擎 AI 面试候选人）作为**隔离的第二产品线**。同一核心引擎（简历×JD→出题+评估+报告），两类受众。

## 非目标

第一阶段不做：

- 传统招聘方 ATS（仅用于筛人/打分淘汰候选人）。
- 真人面试官撮合。
- 伪造工作经历或绕过招聘诚信的能力。
- 未经用户授权抓取第三方平台隐私数据。
- 用 AI 结果替代用户对职业选择的最终判断。

长期硬约束：C 端求职者数据与企业招聘侧**物理隔离、永不互通**；绝不把求职者的练习数据用于企业筛人，绝不出卖求职者数据。企业招聘侧企业为 controller、平台为 processor。

## 产品原则

- 面试训练必须可复盘，而不是只聊天。
- AI 输出必须有证据来源、置信度和结构化结果。
- 用户隐私优先，简历和面试记录默认私密。
- 先做深一个闭环，再扩展到更多职业规划能力。
- 长期数据要沉淀为成长档案和能力曲线。
