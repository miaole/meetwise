# 外部开放材料检索基线（2026-08-03）

## 1. 结论

当前检索增强生成（RAG）不能形成生产质量结论。最强已测路径是“稠密向量候选 + BM25（词项匹配）+ RRF（倒数排名融合）+ rerank（重排序模型）”：在 55 条人工标注、非逐字复述 query（查询）上，段落级 Hit@5（前五命中率）为 92.7%（51/55），其 Wilson 95% 下界为 82.7%。这个下界、样本量和来源分布都不足以支撑线上承诺。

无精排的 RRF 段落级 Hit@5 为 89.1%（49/55），Recall@5（前五召回率）为 72.4%。人工智能方向的无精排 Recall@5 为 38.1%（4/11），是当前最大质量缺口。

## 3. 段落级结果

段落级要求返回人工标注的支持段落，而不是同一文件的任意位置。

| 路径 | Hit@5 | Recall@5 | strict-all（全部证据命中） | MRR（平均倒数排名） | nDCG（归一化折损累计增益） | MAP（平均精确率均值） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| dense（稠密向量） | 85.5% | 72.4% | 78.2% | 0.785 | 0.781 | 0.745 |
| BM25 | 60.0% | 47.1% | 52.7% | 0.533 | 0.527 | 0.499 |
| RRF | 89.1% | 72.4% | 80.0% | 0.763 | 0.772 | 0.726 |
| oracle track RRF（假设方向判断完全正确） | 85.5% | 69.0% | 76.4% | 0.742 | 0.745 | 0.702 |
| RRF + rerank | 92.7% | 73.6% | 85.5% | 0.842 | 0.834 | 0.796 |

`oracle track RRF` 并没有胜过全局 RRF，说明不能把“加一个意图/方向判断器”当作所有 RAG 的默认优化；错误或过窄的方向过滤会剔除有用证据。只有路由会改变权限、工具、成本或工作流时，才应单独训练和验证路由器。

RRF@40 的候选 Recall 为 97.7%。因此段落级丢失主要发生在候选精排到前五的位置，而非全部候选都没有证据；但 2.3% 的候选池缺失仍不能由任何精排补回。

## 4. 来源文档视图

为防止段落标签过严或文档命中率掩盖段落错误，结果额外折叠同一文件/结构化节点：

| 路径 | 来源文档 Hit@5 | 来源文档 Recall@5 | MRR |
| --- | ---: | ---: | ---: |
| dense | 92.7% | 92.7% | 0.873 |
| BM25 | 78.2% | 78.2% | 0.733 |
| RRF | 96.4% | 96.4% | 0.877 |
| RRF + rerank | 98.2% | 98.2% | 0.964 |

来源文档命中率不能替代段落级引用。比如精排会把 CSS（层叠样式表）特异性 query 带回同一文件的开头段落，却未命中人工标注的计算规则段落；这对“展示关联材料”可能足够，对可验证回答不够。

## 5. 方向分层与失败模式

| 方向 | RRF Hit@5 | RRF Recall@5 | 样本数 |
| --- | ---: | ---: | ---: |
| 前端 | 90.9% | 64.0% | 11 |
| 后端 | 100.0% | 100.0% | 11 |
| 人工智能 | 63.6% | 38.1% | 11 |
| Python | 90.9% | 85.7% | 11 |
| 测试工程 | 100.0% | 100.0% | 11 |

无精排的 6 个零命中样本中，4 个来自人工智能方向：短视频指标、搜索召回与排序、内容检测的发布后监控，以及一个“粗筛再精排”的跨方向 query。另有前端输入竞态和 Python 列表/元组 query 零命中。它们不能被平均分掩盖。

段落级未完整命中的多证据样本包括：盒模型（5/13 段）、监督/无监督学习（1/2）、检索指标解释（1/4）、文本特征预处理与编码（1/4）、多线程（1/2）。其中大分母样本反映“一个主题的多段证据”要求，不等于单段答案必然错误；它仍然说明当前 chunk（分区块）设计对多证据聚合不足。

## 6. 无答案结果

只用余弦相似度阈值不能作为安全或业务拒答器。6 条无答案 query 的阈值曲线如下：

| 阈值 | 可回答误拒绝 | 无答案抑制 | 无答案误接收 |
| --- | ---: | ---: | ---: |
| 0.45 | 0.0% | 83.3%（5/6） | 16.7%（1/6） |
| 0.50 | 3.6%（2/55） | 83.3%（5/6） | 16.7%（1/6） |
| 0.55 | 14.5%（8/55） | 100.0%（6/6） | 0.0% |
| 0.60 | 34.5%（19/55） | 100.0%（6/6） | 0.0% |

0.45 会放行提示词注入类 query；0.55 虽压住了此小集全部无答案，却拒绝 8/55 条可回答 query。实际系统必须先用策略规则拒绝高风险和越权请求，再用上下文状态判定指代是否可解析，最后才让检索置信度参与澄清或降级；不能只设一个相似度阈值。

## 8. 下一步门槛

1. 不允许把上述外部文本直接发布。先完成来源审查、许可证履约、内容时效与人工质量审核。
2. 单独创建未参与策略选择的盲测集：至少 200 条可回答 query、50 条无答案/越权/指代缺失 query，并要求两名标注者独立标注、记录一致性。
3. 为人工智能方向重做语义分层：系统设计文档按“问题定义、指标、候选生成、排序、服务、监控”保留标题路径；多证据回答必须有聚合和引用覆盖度门。
4. 把 rerank 保持为候选路径，先在独立盲测集比较质量增益、p95 延迟、失败率和每请求金额，再决定是否灰度。
5. 实现规则优先的越权拒绝、会话指代解析和澄清状态机；相似度阈值只能作为辅助信号。
