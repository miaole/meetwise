# 外部开放材料检索验证协议

## 1. 目的与边界

本协议验证检索增强生成（RAG）的候选证据排序能力。它不验证生成回答的事实性、引文接地、访问控制、数据合规、模型安全、线上容量或商业内容授权。

材料只允许存放在 `.tmp` 的隔离快照中。任何材料进入发布语料前，必须由内容、法务和安全负责人分别审批；本协议的通过结果不能替代该审批。

## 2. 来源快照

每次运行必须校验下列字段并写入 `manifest.json`：

| 字段 | 作用 |
| --- | --- |
| repository | 上游仓库地址 |
| revision | 固定 Git 提交标识，防止同一地址内容漂移 |
| license | 许可证声明；当前隔离验证仅接收 MIT（麻省理工学院许可证） |
| source_path | 原始文件或结构化节点位置 |
| sha256 | 分区块内容哈希，支持复核与去重 |
| fetched_at | 抓取时间 |

快照中的第三方正文不得提交到本仓库。提交物只能包含解析程序、人工标签、度量协议与不含正文的结果元数据。

## 3. 覆盖范围

冻结的首轮快照必须横跨前端、后端、人工智能、Python（Python 编程语言）和测试工程五个方向。每条 query（查询）由人工编写，禁止从目标段落逐字摘取，并标注：

- 目标方向与目标来源分区；
- 口语、省略指代、拼写异常、代码片段、中文与英文混写等压力标签；
- 无答案或越界标签；
- 证据分区的人工标注。

“oracle track filter（完美方向过滤）”只用于衡量路由上限。它假设方向判断完全正确，不能作为线上效果或发布指标。

## 4. 指标

| 指标 | 计算 | 回答的问题 |
| --- | --- | --- |
| Hit@5（前五命中率） | 前五结果至少有一个人工标注证据 | 用户能否看到至少一条正确证据 |
| Recall@5（前五召回率） | 前五结果命中的标注证据数 / 标注证据总数 | 多证据查询漏掉多少材料 |
| MRR（平均倒数排名） | 每条 query 的第一个正确证据排名倒数的均值 | 首条正确证据是否靠前 |
| nDCG（归一化折损累计增益） | 按排名折损后的相关性与理想排序之比 | 多条正确证据的排序质量 |
| MAP（平均精确率均值） | 每条 query 的平均精确率再取均值 | 整体精确排序质量 |
| Wilson 95% 下界 | 二项命中率的保守置信下界 | 小样本高分是否可能偶然出现 |

所有结果必须同时报告分母、方向分层、失败样本和候选池上限。不得只报告一个百分比。

每个策略还必须输出“来源文档视图”：把同一文件或结构化节点的多个分区块折叠后再计算指标。它用于区分“找到了正确文件但没有找准支持段落”与“完全找错来源”。来源文档视图不是引用质量指标，回答生成仍必须使用段落级证据。

## 5. 执行与产物

```bash
pnpm -C apps/worker exec tsx smoke/oss-track-retrieval-eval.ts --source-dir .tmp/rag-open-source-Rd7hGi --dry-run
pnpm -C apps/worker exec tsx smoke/oss-track-retrieval-eval.ts --source-dir .tmp/rag-open-source-Rd7hGi
pnpm -C apps/worker exec tsx smoke/oss-track-retrieval-eval.ts --source-dir .tmp/rag-open-source-Rd7hGi --rerank
```

脚本输出：

- `manifest.json`：来源、revision、许可证、哈希、query 标签和证据标注；
- `result.json`：真实嵌入模型下的 dense（稠密向量）、BM25（词项匹配）和 RRF（倒数排名融合）结果；
- 可选的 rerank（重排序模型）对照：仅在显式 `--rerank` 时调用，保存每次请求的检查点、重试次数与 p50/p95 延迟；
- 无答案相似度阈值曲线：仅用来展示误接收与误拒绝的权衡，不能作为安全决策；
- 内容寻址向量缓存：重跑不重复发送已计算文本，减少成本并支持中断续跑。

## 6. 发布前缺口

以下项目尚未被此协议覆盖，缺少任一项时不得形成线上质量结论：

1. 来自真实 C 端与 B 端场景的脱敏语料，覆盖文档、表格、演示文稿、音视频转写与图片文字。
2. 至少两名独立标注者的证据一致性与裁决记录。
3. 回答级别事实性、引文定位、无答案澄清、越权拒绝和跨租户隔离验证。
4. 检索成本、缓存命中率、失败原因、索引版本、回滚、灰度与告警数据。
5. 在目标数据规模和并发下的端到端延迟、错误率、恢复时间和容量验证。
