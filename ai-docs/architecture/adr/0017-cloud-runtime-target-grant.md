# ADR-0017 云端迁移目标授权与独占测试目标 · proposed

## 背景

项目已购入一个私网 RDS（关系型数据库服务）PostgreSQL 17 基础版单节点**测试实例**，但 Tair Redis（托管内存键值数据库）和 OSS（对象存储服务）的数据面尚无可验证接线；现有部署仍可连接本地 Docker（容器运行环境），而版本化基线迁移中包含破坏性 `DROP`。仅依据数据库名、环境变量、hostname（主机名）允许列表或“这是 staging（预发布环境）”文字，不能阻止脚本误连云端业务库。

该测试 RDS 已启用 TLS（传输层加密），但没有同 VPC（虚拟私有云）运行器；它是单节点基础版，未启用磁盘加密，且没有高可用或恢复演练证据。因此本决策定义未来实现约束，不把当前资源表述为生产可用或已验证。

## 决定

1. 每次迁移或破坏性 E2E（端到端）先由控制面创建 `TestTargetProvisionRun`（测试目标供给任务）：独占数据库/实例、独占 Tair 前缀或专用故障实例、独占 OSS run 前缀。
2. 控制面签发一次性 `TargetGrant`（目标授权），将云账号、地域、RDS 实例、VPC、数据库、环境、允许操作、计划 manifest、run ID、对象/缓存前缀、运行器身份和镜像 digest（内容摘要）不可变绑定；`issued → leased → executing → consumed` 用 CAS（比较并交换）持久化。一个 `executing` lease 可完成其绑定的多阶段迁移，只有终态补偿后消费，重放仍为 0。
3. 控制面只向已执行授权的运行器发放与 `grant_id` 绑定的短期凭据；每个破坏性阶段在线检查撤销。控制面失联、授权重复、过期、撤销或资源漂移均 fail-closed（故障关闭），撤销后不能进入下一阶段且必须解冻源端。长期服务使用不授予破坏性权限的 `ReleaseAttestation`（发布证明），不复用 TargetGrant。
4. 迁移只允许前向兼容变更；已切流后的“回滚”定义为服务回切和独立目标恢复，而不是假定逆向 SQL（结构化查询语言）一定安全。
5. `schema_migrations`（迁移账本）不存在、损坏或 checksum（校验和）不匹配而业务表非空时，迁移器必须在第一条 DDL（数据定义语言）前退出。

## 被否方案

| 方案 | 否决原因 |
| --- | --- |
| 数据库名前缀或环境变量允许列表 | 可被同名库、变量污染、DNS（域名解析）漂移或错误账号绕过，不能提供不可伪造信任根。 |
| 共享 staging 运行破坏性 E2E | 破坏性基线、故障注入和并发清理会污染其他验证，无法给出 run 级证据。 |
| 本地 Docker 代替云端数据面 | 无法验证私网、Tair TLS、OSS 权限、云端恢复或真实成本/延迟。 |
| 长期高权数据库口令 + 应用侧签名校验 | 进程一旦取得口令即可绕过授权直接执行 SQL；在短期凭据代理实现前，破坏性运行保持阻断。 |
| 把数据库恢复当作每次发布的普通回滚 | 已提交的 DDL、外部副作用和长会话检查点不一定可逆，会制造数据丢失风险。 |

## 后果与失败模式

- 成本：需要控制面、短期凭据代理和同 VPC 运行器；未具备时真实云端运行只能标为 `blocked`，不能以假测试代替。
- 防重放：同一 `TargetGrant` 的并发租用只有一个 CAS 胜者，`executing` 期间仅允许绑定的执行链；过期或撤销后的所有新阶段均拒绝。
- 一致性：迁移在源冻结后记录 LSN（日志序列号）和内容 HMAC（哈希消息认证码）摘要；仅行数或主键相同不能通过。
- 清理：目标供给任务只清理本 run 创建的资源；版本化 OSS 对象按保留期区分“线上不可读”和“物理删除完成”。
- 验证：全部主流程及 E1–E6（重复、并发、越权、失败、降级、超时）对应独立 TC（测试用例），见云端测试矩阵。当前真实云端 TC 均未通过，不得引用为生产证据。
